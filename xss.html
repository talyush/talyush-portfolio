XSS Vulnerabilities

When websites trust user input a little too much

What is XSS?

Cross-Site Scripting (XSS) is a vulnerability that lets attackers inject malicious JavaScript into web pages. When the victim loads the page, the script executes inside their browser — as if it were a trusted part of the site.

Why is it Dangerous?

Because a successful XSS attack can:

  • Steal cookies & session tokens
  • Impersonate users and perform actions on their behalf
  • Modify page content and redirect users
  • Spread worms across the site
  • Install keyloggers and malware

Vulnerable Example

<input type="text" name="username">

<!-- Attacker injects: -->
<script>alert('XSS')</script>
⚠️ Vulnerable Output:
The script executes because the input is not sanitized before rendering.

Secure Implementation

// Input sanitization
function sanitize(input) {
return input.replace(/[&<>"']/g, function(m) {
return { '&': '&', '<': '<', '>': '>', '"': '"', "'": ''' }[m];
});
}

// Output encoding
escapeHTML(userInput)
✅ Secure Output:
Special characters are escaped, preventing script execution.

Defense Strategies

  • Always sanitize user input — Never trust data from users
  • Use Content Security Policy (CSP) — Restrict script sources
  • Escape HTML before rendering — Convert special characters
  • Avoid inline JavaScript — Use event handlers instead
  • Use HTTPOnly cookies — Prevent JavaScript access
  • Implement proper CORS — Control cross-origin requests

Types of XSS

Stored XSS: Malicious script is stored on the server and executed when users access the affected page.

Reflected XSS: Malicious script is reflected off a web server, such as in an error message or search result.

DOM-based XSS: Vulnerability exists in client-side code rather than server-side code.

Important: XSS remains one of the most common web vulnerabilities. Always implement proper input validation and output encoding.
